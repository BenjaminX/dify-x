Three Contracts · 把“做得不错”写成可检查条件

Agent 上线前，先签三份机器可执行的契约。

01 · TASK CONTRACT任务契约

输入、完成条件、质量阈值、停止条件。

缺失 → 系统不知道何时算完成
02 · TOOL CONTRACT工具契约

身份、权限、预算、前置与后置条件。

缺失 → 模型建议直接变成越权动作
03 · EVIDENCE CONTRACT证据契约

必须保存的输入、来源、动作、版本和审批。

缺失 → 事后只能看到一段答案
时长 2:15。核心讲法：任务契约回答什么叫完成，工具契约回答允许做什么，证据契约回答如何证明做过什么。三份契约缺一，分别导致漫游、越权和不可审计。术语：机器可执行表示关键条件进入流程配置、工具模式或日志字段，而不只写在制度文档。过渡：先深入第一类基础——模型究竟需要什么上下文才能理解任务。证据边界：三契约是本讲座的系统设计抽象，不对应 Dify 的三个固定产品对象。
